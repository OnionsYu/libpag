## 一、图层模型与术语

### 1.1 PSD 不是“若干张 PNG 的集合”

PSD 可以同时保存图层像素、文字排版、矢量路径、智能对象引用、调整参数、蒙版、样式、文档资源，以及整张图的合成结果。读取到图层像素，只完成了图层信息的一部分。

建议按以下关系理解图层：

```text
Document
├── 画布尺寸、颜色模式、位深、分辨率、ICC 配置
├── 图层树
│   ├── 普通图层
│   │   ├── 内容：像素 / 文字 / 形状 / 智能对象 / 调整参数
│   │   ├── 通用属性：ID、名称、可见性、不透明度、混合模式
│   │   ├── 蒙版：像素蒙版、矢量蒙版及其参数
│   │   └── 样式与高级混合设置
│   └── 图层组或画板
│       ├── 自身属性、蒙版、混合设置
│       └── 子图层
├── 资源：字体引用、图案、链接内容、色彩资料、图层复合等
└── 合成图像数据
```

### 1.2 容易混淆的概念

| 概念 | 含义 | 不应混为一谈的对象 |
| --- | --- | --- |
| 图层记录 Layer Record | 二进制文件中的一条结构记录 | 不一定对应一个用户可见的内容图层；可能是组边界 |
| 图层组 Group | 包含子图层的层级容器 | 不是单纯加了名称前缀的一组普通图层 |
| 画板 Artboard | 带独立输出边界及相关属性的特殊容器 | 普通图层组、文档整张画布 |
| 像素透明度 | 每个像素的透明程度，通常来自图层透明通道 | 图层整体不透明度 |
| 图层不透明度 Opacity | 图层整体参与合成的强度 | 填充不透明度 Fill |
| 填充不透明度 Fill | 主要调节图层内容，保留样式的独立作用 | 简单地把整个图层最终结果乘一次透明度 |
| 像素蒙版 | 按像素控制显隐的灰度数据 | 图层自身的透明通道 |
| 矢量蒙版 | 使用路径定义显隐范围 | 形状填充参数；普通像素蒙版 |
| 剪贴蒙版 Clipping Mask | 上方图层受下方基底图层的形状约束 | 图层内部独立保存的一张灰度蒙版 |
| 图层样式 Layer Effects | 投影、描边、发光等附着效果 | 一定独立存在的像素图层 |
| 图层复合 Layer Comp | 文档内保存的一组可见性、位置或外观状态 | 重新复制的一棵完整图层树 |
| 合成图 Composite | 整个文档某个状态的最终像素结果 | 每个图层的像素缓存、文件缩略图 |

Opacity、Fill 和组的 Pass Through 行为，可参见 [Adobe 图层不透明度与混合模式说明][adobe-opacity]。

### 1.3 建议保存的图层通用属性

以下为**实现建议**，是解析后的中间数据模型，不是 PSD 文件头中的一个现成对象。

| 属性 | 推荐表示 | 说明 |
| --- | --- | --- |
| `sourceLayerId` | 可空的整数 | 优先使用 `lyid`；不存在时不要伪造为“原文件 ID” |
| `internalId` | 工具内部唯一标识 | 处理缺失或重复原始 ID，保证内部引用可用 |
| `name` | Unicode 字符串 | 优先使用 `luni`，保留原始名称 |
| `kind` | 枚举 | 像素、文字、形状、填充、调整、智能对象、组、画板、未知 |
| `parent` / `children` | 层级关系 | 与原始记录序号分别保存 |
| `fileRecordIndex` | 整数 | 原文件中的记录位置，便于诊断和回写 |
| `visible` | 布尔值 | 当前图层自己的可见状态 |
| `effectiveVisible` | 计算结果 | 当前图层及祖先组都允许显示时才可能可见 |
| `opacity` / `fillOpacity` | 统一范围的数值 | 内部可用 `0..1`；保留原始 `0..255` 便于无损回写 |
| `blendMode` | 原始四字节 key + 已识别枚举 | 不认识的值也要保留 |
| `pixelBounds` | 带符号矩形 | 图层通道数据对应的范围 |
| `visualBounds` | 可空矩形 | 渲染后的范围，可能受样式、变换影响 |
| `clippingBase` | 可空引用 | 归一化后指向实际剪贴基底 |
| `masks` | 可空对象集合 | 分开保存像素、真实像素、矢量蒙版及参数 |
| `effects` / `content` | 类型化对象 + 原始数据 | 便于编辑、渲染以及保留未知字段 |
| `rawTaggedBlocks` | 有序块列表 | 保存 key、长度、原始 payload 和原始顺序 |
| `diagnostics` | 列表 | 记录缺失资源、未支持特性与降级方式 |

不要把“名字相同”“像素尺寸相同”或“缩略图相同”当作图层身份相同。PSD 允许同名图层，图层顺序也会随编辑而改变。

## 二、PSD/PSB 二进制结构

### 2.1 通用编码规则

**格式事实与实现约定：**

- PSD 结构中的多字节基础数值采用大端序；不要使用宿主机默认字节序直接读取。嵌入的 JPEG、PNG、智能对象源文件等载荷遵循各自格式，不应对其统一做字节交换。
- 本文的 `u16`、`u32`、`u64` 表示无符号整数；`i16`、`i32` 表示有符号整数；`f64` 表示 8 字节浮点数。
- 图层矩形坐标、图层计数、通道 ID 中有需要按有符号数读取的字段。
- 四字符标识是**精确的 4 字节值**，区分大小写，尾随空格不能删除。例如 `mul `、`div `、`hue `。
- 长度通常表示其后数据的字节数；每一层结构均须单独判断是否包含 padding，不能套用一个全局对齐规则。
- Unicode 字符串通常以 `u32` 长度开头，长度按 UTF-16 代码单元计算，随后读取对应的 UTF-16BE 字节。
- 不要用 UTF-8 字节数、中文字符数或 Unicode 码点数替代 UTF-16 代码单元数。带代理对的字符尤其容易读错。
- 按字符串声明长度消费数据。是否去掉末尾空字符属于字段解释或显示处理，不应再无条件多消费两个字节。

### 2.2 文件整体布局

```text
File Header                         固定 26 字节
Color Mode Data                     u32 长度 + 数据
Image Resources                     u32 长度 + 资源块
Layer and Mask Information          PSD: u32 长度；PSB: u64 长度
Image Data                          合成图像，至文件尾
```

五个部分按上面的顺序出现。合成图像位于最后一部分；不能把图层与蒙版部分当作整张合成图。

#### 文件头字段

| 偏移 | 字节数 | 类型 | 含义 |
| --- | ---: | --- | --- |
| 0 | 4 | ASCII | 签名 `8BPS` |
| 4 | 2 | `u16` | `1` 为 PSD；`2` 为 PSB |
| 6 | 6 | 字节 | 保留字段，规范要求为零 |
| 12 | 2 | `u16` | 文档合成图通道数，公开规范范围为 `1..56` |
| 14 | 4 | `u32` | 文档高度，单位 px |
| 18 | 4 | `u32` | 文档宽度，单位 px |
| 22 | 2 | `u16` | 每通道位深：`1`、`8`、`16`、`32` |
| 24 | 2 | `u16` | 颜色模式 |

颜色模式值：`0` Bitmap，`1` Grayscale，`2` Indexed，`3` RGB，`4` CMYK，`7` Multichannel，`8` Duotone，`9` Lab。该枚举不表示所有模式、位深、图层和混合功能都可以任意组合。

格式字段及结构来源：[Adobe PSD/PSB 文件格式规范][adobe-format]。

### 2.3 PSD 与 PSB 的差异

| 项目 | PSD | PSB |
| --- | --- | --- |
| 文件头版本 | `1` | `2` |
| 文档单边尺寸上限 | 30,000 px | 300,000 px |
| Photoshop 常规保存文件大小边界 | 2 GB | 面向超出 PSD 限制的大文档 |
| 图层与蒙版区总长度 | 4 字节 | 8 字节 |
| 主 Layer Info 长度 | 4 字节 | 8 字节 |
| 单图层的通道数据长度 | 4 字节 | 8 字节 |
| RLE 每行压缩长度 | 2 字节 | 4 字节 |
| Additional Layer Information 长度 | 通常 4 字节 | 指定 key 使用 8 字节，不能全部改成 8 字节 |
| 文件头宽高 | 4 字节 | 仍为 4 字节 |
| 颜色数据区、资源区总长度 | 4 字节 | 仍为 4 字节 |
| Layer Record 的 Extra Data 长度 | 4 字节 | 仍为 4 字节 |

PSB 不是“把 PSD 所有整数都换成 64 位”。不要仅凭扩展名识别版本。尺寸与保存限制参见 [Adobe 大型文档保存说明][adobe-large]；字段宽度参见 [Adobe 格式规范][adobe-format]。

### 2.4 图层与蒙版区

```text
LayerAndMaskInformation
├── sectionLength
├── LayerInfo
│   ├── layerInfoLength
│   ├── signedLayerCount
│   ├── LayerRecord[abs(signedLayerCount)]
│   └── ChannelImageData：按记录顺序、记录内通道顺序保存
├── GlobalLayerMaskInfo
└── 文档级 Tagged Blocks
```

需要特别处理：

1. `sectionLength == 0` 时，此区没有后续内容，不应继续读取图层计数。
2. 图层计数为 `i16`。负数的绝对值是记录数；负号还表明合成结果的首个 Alpha 通道承载透明度信息。
3. 所有图层记录先连续保存，之后才是所有图层的通道数据。不能读完一条记录就立即把当前位置当作该图层像素。
4. 主 Layer Info 长度按规范补齐到偶数字节。
5. 高位深文档还需要检查 `Lr16`、`Lr32` 等附加块。主 Layer Info 为空，不足以判定文档没有图层。
6. `Layr`、`Lr16`、`Lr32` 的载荷包装与主 Layer Info 不完全相同；已经由外层块给出长度时，不要重复读取一个不存在的长度字段。
7. 全局图层蒙版区与每个图层自己的蒙版区是两种结构，不能复用同一个字段布局。

全局蒙版区以 `u32` 长度开头，公开字段包括颜色空间、4 个颜色分量、`0..100` 不透明度和 kind。它不等价于给每个图层附加一张灰度蒙版。

### 2.5 单条 Layer Record

| 顺序 | 字节数 | 字段 | 解析要求 |
| --- | ---: | --- | --- |
| 1 | 16 | `top, left, bottom, right` | 四个 `i32`，图层像素矩形 |
| 2 | 2 | `channelCount` | `u16` |
| 3 | PSD 为 `6 × N`；PSB 为 `10 × N` | 通道表 | 每项为 `i16 id` + `u32/u64 length` |
| 4 | 4 | 混合模式签名 | `8BIM` |
| 5 | 4 | 混合模式 key | 原样保留 4 字节 |
| 6 | 1 | `opacity` | `0..255` |
| 7 | 1 | `clipping` | `0` 为基底；`1` 为被剪贴的非基底层 |
| 8 | 1 | `flags` | 位标志 |
| 9 | 1 | filler | 零填充 |
| 10 | 4 | `extraDataLength` | 此后额外数据的总长度 |
| 11 | 可变 | Extra Data | 蒙版、混合范围、旧名称、附加块 |

矩形的常用解释为半开区间：`[left, right) × [top, bottom)`。宽为 `right-left`，高为 `bottom-top`。

- `left`、`top` 可以小于零；`right`、`bottom` 可以超出画布。
- 空图层和结构记录可以是零宽、零高。
- 不能把图层的像素矩形直接当作包含阴影、描边后的视觉矩形。
- 对负宽高、整数溢出和越过文件边界的长度应报错；不要分配按错误长度计算的缓冲区。

#### flags 的解释

以下位编号从 `0` 开始。

| 位 / 掩码 | 含义 | 处理方式 |
| --- | --- | --- |
| bit 0 / `0x01` | 透明像素保护 | 保留为锁定属性 |
| bit 1 / `0x02` | 隐藏标志 | **置位表示隐藏**；`visible = (flags & 0x02) == 0` |
| bit 2 / `0x04` | 旧字段 | 保留原值 |
| bit 3 / `0x08` | bit 4 的有效性标志 | 与 bit 4 配合解释 |
| bit 4 / `0x10` | 像素数据不直接决定外观 | 不表示该记录可以删除；形状、调整、组等可能使用 |
| bit 5..7 | 未在旧公开表中完整说明 | 保留，不任意清零 |

**文档歧义修正：** Adobe 旧表把 bit 1 简写为 visible，容易被误读为“置位可见”。公开实现采用反向逻辑；本机样本中可见图层的这一位也为零。参见 [psd-tools 的 LayerFlags 实现][psd-layer-source]。本次样本没有覆盖所有隐藏组合，生产实现仍应加入专门的隐藏图层样本。

### 2.6 通道表与像素数据

| 通道 ID | 含义 |
| ---: | --- |
| `0, 1, 2, ...` | 颜色通道；含义由文档颜色模式决定 |
| `-1` | 图层透明度通道 |
| `-2` | 用户图层蒙版通道；部分情况下可能是由其他数据生成的蒙版缓存 |
| `-3` | 真实用户蒙版通道，用于区分某些同时存在多种蒙版的情况 |

RGB 模式下 `0/1/2` 才对应 R/G/B。CMYK、Lab 等不能按 RGB 顺序直接解释。通道以平面形式保存，不是交错排列的 RGBA 像素。

每个通道的 `length` **包括开头的 2 字节压缩方法字段**。相邻通道可能使用不同压缩方式。本机样本中，同一图层已经出现 RLE 与 Raw 混用。

颜色通道与透明度通道一般使用图层矩形；蒙版通道使用对应蒙版矩形。`-3` 应结合真实蒙版的边界读取，不能复用 `-2` 的尺寸。

#### 压缩方法

| 编码 | 方法 | 读取要点 |
| ---: | --- | --- |
| `0` | Raw | 按通道尺寸和位深读取未压缩数据 |
| `1` | RLE / PackBits | 先读各行压缩长度，再逐行解码 |
| `2` | ZIP，无预测 | 解压 zlib 数据后得到通道样本 |
| `3` | ZIP，有预测 | zlib 解压后还必须执行预测还原 |

对单通道、已确定的宽高，未压缩大小按下式计算：

```text
rowBytes     = ceil(width × depth / 8)
decodedBytes = rowBytes × height
```

1 位数据按行打包；16 位数据需要按对应样本宽度处理；32 位图像需要考虑浮点数据，不能直接截断为 `0..255`。

**RLE 规则：** 每个通道先保存 `height` 个行长度。PSD 每项 `u16`，PSB 每项 `u32`。PackBits 控制字节若按有符号数 `n` 解释：

- `0 ≤ n ≤ 127`：复制其后 `n+1` 个字节。
- `-127 ≤ n ≤ -1`：把其后一个字节重复 `1-n` 次。
- `n == -128`：空操作。

每行解码结果应与 `rowBytes` 一致。不要把压缩行长度当成像素数量，也不要让某一行越界消费下一行的数据。

**ZIP 预测还原：** 8 位按行还原相邻字节差分；16 位按行还原 16 位样本差分；32 位还涉及字节平面重排，不能套用 8 位逻辑。各步都应校验输出长度。实现细节可交叉参考 [psd-tools 压缩代码][psd-compression-source]。

**对齐注意：** 不能因为图层宽度是奇数，就自行给每一条 Raw 行插入补齐字节。本机样本中一个 679 × 453 的 8 位 Raw 通道，长度为 `2 + 679 × 453 = 307589`，没有逐行补齐。压缩区的消费以通道长度和对应编码规则为准。

### 2.7 Extra Data 的内部结构

```text
ExtraData
├── maskDataLength: u32
├── maskData
├── blendingRangesLength: u32
├── blendingRanges
├── legacyLayerName: Pascal string，整个字段补齐到 4 字节
└── Additional Layer Information blocks
```

Pascal 旧名称的首字节是字节长度，后面跟随名称数据。其编码不保证为 UTF-8。遇到 `luni` 时优先使用 Unicode 名称，同时保留旧名称原始字节以便回写。

#### Blend If / 混合范围

混合范围包含合成灰度和各颜色通道的源、目标范围。单个 4 字节范围由两端的黑、白阈值组成，拆分滑块会产生过渡范围。

该数据影响当前层与底图在什么亮度范围内参与合成，不能用一个全局 Alpha 值替代。未实现 Blend If 时，应记录外观可能改变，并选择可复现的预渲染或明确失败策略。

### 2.8 像素蒙版结构

`maskDataLength == 0` 表示没有这一段蒙版数据；非零时按长度和 flags 判断可选字段，不要只接受两个固定长度。

| 字段 | 常见大小 | 含义 |
| --- | ---: | --- |
| `top, left, bottom, right` | 16 字节 | 蒙版矩形 |
| `defaultColor` | 1 字节 | 蒙版矩形以外的默认值，常见为 0 或 255 |
| `flags` | 1 字节 | 相对位置、禁用、来源和参数等状态 |
| 可选参数标志 | 1 字节 | 决定后续 density / feather 是否存在 |
| 可选 density | 每项 1 字节 | 像素或矢量蒙版浓度 |
| 可选 feather | 每项 8 字节 | 像素或矢量蒙版羽化量，double |
| 可选真实蒙版字段 | 18 字节 | 真实 flags、默认值、独立矩形 |
| padding | 依布局而定 | 只按相应结构消费 |

蒙版 flags 从 bit 0 开始依次描述：位置是否相对图层、是否禁用、旧反相标志、是否由其他数据生成，以及是否存在附加参数。参数标志的 bit 0..3 分别对应像素浓度、像素羽化、矢量浓度、矢量羽化。

**实现建议：**

1. 蒙版灰度通常按黑隐藏、白显示解释；灰度产生部分覆盖。
2. 使用 `defaultColor` 解释矩形以外的区域，否则小矩形蒙版可能误遮住整个图层。
3. 蒙版被禁用时保留数据，但不施加该蒙版效果。
4. 根据位置标志完成坐标换算，分别保存蒙版与图层的位置。
5. 浓度与羽化是参与渲染的参数，不要只读取蒙版位图。
6. 像素蒙版、矢量蒙版与其栅格缓存要区分来源，避免把同一个限制重复施加。
7. 样式是否受蒙版影响，还与 `lmgm`、`vmgm`、`tsly` 等设置有关，不能只用一个统一乘法覆盖所有情况。

### 2.9 附加图层信息 Tagged Blocks

基本结构为：

```text
signature       4 bytes：8BIM 或 8B64
key             4 bytes
payloadLength   按容器版本与 key 选择 4 或 8 bytes
payload         按 key 解释
padding         按当前容器及块规则处理
```

附加块既可以出现在图层的 Extra Data 中，也可以出现在文档级图层与蒙版区尾部。它们的作用域不同。

公开规范为 PSB 列出的 64 位长度 key 包括：`LMsk`、`Lr16`、`Lr32`、`Layr`、`Mt16`、`Mt32`、`Mtrn`、`Alph`、`FMsk`、`lnk2`、`FEid`、`FXid`、`PxSD`。较新实现还维护扩展集合，不能把这份旧表当作未来所有 key 的全集。

**实现建议：** 不要只看到 `8B64` 就把当前所有长度都切换为 64 位；使用明确的版本/key 规则。对新出现且无法确定长度宽度的 PSB 块，应停止对该父区做推测式解析并保留原区。

对齐也应按上下文处理：图层内很多块的声明长度已经包含内部填充；文档级附加块常按 4 字节边界放置。不要读完一个已含填充的 payload 后再次无条件对齐。当前公开解析器的图层与文档级读取路径也使用不同 padding 参数，参见 [Tagged Blocks 实现][psd-tags-source]。

#### 常见 key 速查

| key | 内容 | 主要用途 |
| --- | --- | --- |
| `luni` | Unicode 图层名 | 中文、长名称、非 ASCII 字符 |
| `lyid` | 图层 ID | 引用和身份追踪 |
| `lsct`、`lsdk` | 分组分隔信息 | 构造图层树；`lsdk` 需按兼容实现处理 |
| `lspf` | 锁定/保护标志 | 透明像素、内容、位置等保护 |
| `lclr` | 面板颜色标签 | 编辑器组织信息，通常不影响像素 |
| `iOpa` | 填充不透明度 | 与 Layer Record 的 opacity 分开 |
| `TySh` | 文字对象 | 内容、变换、文字与变形描述符 |
| `Txt2` | 文字引擎数据 | 文字系统补充数据，不可直接当纯文本 |
| `vmsk`、`vsms` | 矢量蒙版 | 路径和蒙版状态 |
| `SoCo` | 纯色填充 | 填充内容 |
| `GdFl` | 渐变填充 | 渐变内容 |
| `PtFl` | 图案填充 | 图案引用与参数 |
| `vstk` | 矢量描边设置 | 宽度、位置、虚线等 |
| `vscg` | 矢量描边内容 | 描边颜色或填充内容 |
| `vogk` | 形状来源信息 | 保留某些形状的参数化编辑信息 |
| `lrFX` | 旧式图层样式 | 老版本兼容信息 |
| `lfx2`、`lfxs` | 对象化样式信息 | 新式样式及多效果兼容表示 |
| `PlLd`、`plLd`、`SoLd`、`SoLE` | 置入/智能对象相关信息 | 必须按精确 key 和版本分派，大小写不等价 |
| `lnkD`、`lnk2`、`lnk3`、`lnkE` | 链接或嵌入内容 | 通过内部标识关联对象与源内容 |
| `artb`、`artd`、`abdd` | 画板数据 | 画板属性与输出边界 |
| `clbl`、`infx` | 剪贴层/内部效果混合设置 | 高级合成语义 |
| `knko` | 挖空设置 | 影响与下方层级的合成关系 |
| `tsly`、`lmgm`、`vmgm` | 透明度及蒙版对效果的作用 | 避免蒙版和样式关系失真 |
| `brst` | 通道混合限制 | 限制参与混合的通道 |
| `shmd` | 元数据集合 | 需要保留未知子项 |
| `fxrp` | 参考点 | 编辑及效果相关定位 |
| `lyvr` | 图层解释版本信息 | 兼容性判断 |
| `Lr16`、`Lr32` | 高位深图层信息 | 选择正确图层数据 |
| `Patt`、`Pat2`、`Pat3` | 图案资源 | 图案填充和样式依赖 |
| `FEid`、`FXid` 等 | 滤镜效果数据 | 不等同于普通图层样式 |
| `PxSc`、`PxSD` | 特殊像素来源 | 某些特殊内容或旧功能数据 |

这是一张识别索引，不是各 payload 的完整字段表；也不是 Photoshop 2026 全部私有 key 的清单。Adobe 已公开的块可查 [格式规范][adobe-format]；公开规范未完整覆盖的变体应参考实现、保留原数据并补充样本。

### 2.10 Action Descriptor

文字、填充、样式、画板和智能对象大量使用 Descriptor。不能把这些 payload 当 JSON 或定长结构读取。

基本形式：

```text
Descriptor
├── name：Unicode string
├── classId：u32 长度；为 0 时随后读取四字符 ID，否则读取指定长度字符串
├── itemCount：u32
└── items[itemCount]
    ├── key：与 classId 相同的 ID 编码方式
    ├── valueType：4 字节 OSType
    └── value：按 valueType 递归读取
```

常见 OSType：

| 类型 | 值的含义 |
| --- | --- |
| `Objc`、`GlbO` | 嵌套 Descriptor |
| `VlLs` | 带各项类型信息的列表 |
| `TEXT` | Unicode 字符串 |
| `long`、`comp` | 32 位、64 位整数 |
| `doub` | double |
| `UntF` | 单位标识 + double |
| `bool` | 单字节布尔值 |
| `enum` | 枚举类型 ID + 枚举值 ID |
| `obj ` | 引用对象 |
| `type`、`GlbC` | 类信息 |
| `alis`、`tdta` | 别名或原始数据 |

单位例如 `#Pxl` 像素、`#Pnt` 点、`#Prc` 百分比、`#Ang` 角度。读取参数时必须同时保留单位。

外部块经常带一个值为 `16` 的 Descriptor 版本，但版本字段属于具体包装，不应在每次递归 Descriptor 时无条件读取。遇到未知 OSType，通常没有可通用跳过的长度，应终止当前描述符的语义解析，保留它的外层完整 payload。

### 2.11 文档资源与合成图

图层解释有时依赖 Image Resources。资源块通常包含 `8BIM`、两字节资源 ID、按偶数字节补齐的 Pascal 名称、`u32` 数据长度和按偶数字节补齐的数据。

重点关注：

| 资源 ID | 内容 | 与图层的关系 |
| ---: | --- | --- |
| 1005 | 分辨率 | 点、英寸与像素的单位换算 |
| 1039 | ICC Profile | 正确解释颜色 |
| 1042 | 效果总体可见性 | 图层保存了样式，不代表样式在当前文档状态启用 |
| 1037、1049 | 全局光照角度、高度 | 样式可能引用全局光照 |
| 1044 | 文档 ID 生成种子 | 写入新图层 ID 时需要维护 |
| 1057 | 版本及真实合成数据标记 | 辅助判断合成缓存能否使用 |
| 1060 | XMP | 文档元数据 |
| 1064 | 像素长宽比 | 视频等非方形像素工作流 |
| 1065 | 图层复合 | 不同状态的图层组合 |

文件最后的合成图数据也以压缩方法开头，但 RLE 行长度表面向整张图的各通道；不能直接套用单个图层蒙版的尺寸。缩略图资源与完整合成图应分别处理。

保存时的“最大兼容性”有助于保留供其他应用读取的合成结果，却不会让其他应用自动获得对文字、样式、调整层和智能对象的完整编辑能力。参见 [Adobe 格式规范的合成图说明][adobe-format]。

## 三、不同图层类型的表示与处理

### 3.1 类型识别应使用结构和内容

PSD 没有一个统一的 Layer Record 字段，直接用枚举声明所有现代图层种类。类型通常需要结合附加块、分组标志、内容描述符和通道判断。

| 类型 | 主要识别依据 | 应保留的内容 | 常见错误 |
| --- | --- | --- | --- |
| 像素层 | 常规像素通道，且未发现其他内容语义 | 像素、透明度、位置和附加属性 | 所有有 RGB 通道的层都被当作像素层 |
| 背景层 | 应用语义及保护、位置等相关信息 | 背景身份和不透明内容 | 只按名称 `Background` 判断 |
| 文字层 | `TySh` 等文字对象信息 | 文本、排版、字体、变换、引擎数据 | 只导出文字内容，丢弃样式段 |
| 形状层 | 填充内容 + 矢量路径，可能有描边和形状来源 | 路径、填充、描边、布尔关系 | 任何带 `vmsk` 的层都被当作形状层 |
| 填充层 | `SoCo`、`GdFl`、`PtFl` 等 | 填充参数和可选蒙版 | 与调整层混为同一种颜色运算 |
| 调整层 | `curv`、`levl` 等参数块 | 调整参数、作用范围、蒙版 | 因为像素边界为空而删除 |
| 智能对象 | `SoLd` / `SoLE` / 置入信息及关联资源 | 内容引用、源数据、变换、滤镜 | 把栅格缓存视为完整对象源文件 |
| 图层组 | `lsct` / `lsdk` 的 folder 信息 | 子层、组混合、组蒙版 | 把边界记录变成可见图层 |
| 画板 | 容器结构 + 画板描述信息 | 输出矩形、背景、子层 | 只取子层包围盒作为画板尺寸 |
| 未识别或特殊层 | 未支持的内容块 | 原始记录、资源与可用缓存 | 静默删除或宣称可无损编辑 |

一个智能对象也可以拥有矢量蒙版、像素蒙版和图层样式。因此，“内容类型”和“附着属性”必须分开建模。本机测试文件中，名称为 `vector mask layer` 的层还同时带有智能对象字段。

### 3.2 普通像素层与背景层

普通像素层的基本内容来自颜色通道和透明度通道。文件中的图层矩形表示存储范围，并不保证它恰好包围所有视觉上非透明的像素。

**实现建议：**

- 解码后统一到明确的颜色空间、位深和 Alpha 表示，记录是否预乘。
- 无透明通道时，按图层类型和颜色模式解释覆盖范围；不要把“缺失透明通道”当作所有图层都不透明的充分条件。
- 文件裁剪范围外的像素、组遮罩和画板裁剪应在相应阶段处理。
- 没有像素不等于没有语义。空图层可能是占位符；调整层、组、填充层也可能不依赖常规像素通道。
- 背景层名称可被本地化或修改；在使用 Photoshop API 时，优先读取 `isBackgroundLayer` 等语义属性。

Adobe 的 [UXP Layer API][adobe-layer-api] 区分 `bounds` 与 `boundsNoEffects`。API 边界与 PSD 原始通道矩形也未必相同，应注明具体取值来源。

### 3.3 图层组与图层顺序

`lsct` 的 section type：

| 值 | 含义 |
| ---: | --- |
| `0` | 普通类型，不构成 folder 边界 |
| `1` | 展开的组 |
| `2` | 折叠的组 |
| `3` | 隐藏于面板的组边界记录 |

展开、折叠属于编辑器状态，不等于组可见、不可见。

**样本核验：** 本机样本的原始记录从底层到顶层排列；配套 Generator JSON 则按面板从上到下表达。工具对外暴露的数组可能已经翻转，应明确记录数组的方向。

文件顺序示例：

```text
底部 → 顶部
Background
组边界，type=3
组内底层
组内顶层
Group，type=1 或 2
组外顶层
```

若内部模型采用面板顺序，可逆序遍历文件记录：

```text
stack = [documentRoot]
for record in reverse(fileRecords):
    if record.sectionType is 1 or 2:
        group = createGroup(record)
        appendToCurrentParent(group)
        stack.push(group)
    else if record.sectionType is 3:
        require stack has an open group
        stack.pop()
    else:
        appendToCurrentParent(createLayer(record))
require stack contains only documentRoot
```

这是说明层级处理的伪代码。生产实现还应处理 `lsdk`、高位深层集合、损坏边界和诊断信息，不能仅凭显示名称 `</Layer group>` 匹配分组。

**组混合模式：** section divider 可附带 `8BIM` 和混合模式 key。应读取这个组语义字段；不能只读取 Layer Record 的模式。本机两个组的 Layer Record 均写 `norm`，但 `lsct` 中为 `pass`，配套 JSON 也确认是 Pass Through。

### 3.4 画板

画板通过容器与附加描述信息表达。至少应记录：

- 画板名称与身份。
- 文档坐标中的画板矩形。
- 画板背景设置。
- 子图层及其层级、可见性。
- 画板裁剪与导出范围。

画板坐标、子图层像素坐标、导出文件局部坐标是不同坐标系。导出独立画板时，通常以画板左上角平移到局部原点，再按画板矩形裁剪；不要先丢失原始文档坐标。

若目标工具不支持画板，交付时可拆成多个普通文档或多个场景，同时在说明中记录对应关系。Photoshop 画板功能参见 [Adobe 画板文档说明][adobe-artboards]。

### 3.5 文字层

文字层至少包含以下层次的信息：

| 层次 | 需要保留的内容 |
| --- | --- |
| 字符内容 | 原文、换行、空格、Unicode 字符 |
| 字符样式段 | 字体标识、字号、字重、颜色、字距、基线偏移、缩放等 |
| 段落样式 | 对齐、缩进、段前段后、行距、方向等 |
| 文字对象 | 点文字或段落文字、文本框、方向、路径或变形信息 |
| 几何变换 | 缩放、旋转、倾斜、位置，以及可能的 warp |
| 渲染相关 | 抗锯齿、字体替代、语言与排版引擎信息 |
| 缓存 | 用于兼容显示的像素信息，可能不是最终样式合成结果 |

常见 `TySh` 包装顺序：

| 字段 | 常见布局 |
| --- | --- |
| version | `u16`，常见为 1 |
| transform | 6 个 `f64`：`xx, xy, yx, yy, tx, ty` |
| text version | `u16`，常见为 50 |
| text descriptor version | `u32`，常见为 16 |
| text descriptor | 可变长 |
| warp version | `u16`，常见为 1 |
| warp descriptor version | `u32`，常见为 16 |
| warp descriptor | 可变长 |
| 尾部 bounds | 常见兼容布局为四个 `i32`，再按块长度处理剩余填充 |

**样本核验与文档差异：** Adobe 公开表对最后四个边界值标注了 `4 × 8` 字节；公开解析器使用四个 32 位整数。本机样本在两个 Descriptor 后剩余 19 字节，解析为 16 字节整数边界和 3 字节零填充，可以与块尾精确对齐。因此不能直接按四个 double 读取。参见 [TypeToolObjectSetting 实现][psd-tags-source]。该样本的尾部边界值全部为零，布局检查不能代替对所有文字几何含义的验证。

文字变换可按以下仿射关系理解，但应与目标引擎矩阵约定核对：

```text
x' = xx × x + yx × y + tx
y' = xy × x + yy × y + ty
```

**实现与交付注意事项：**

1. 不应假设一个文字层只有一种字体或一种字号。
2. 字体名称不等于字体文件；PSD 通常不提供可供接收方任意安装的完整字体资源。
3. 文本索引的单位依所属结构而定。不能混用 UTF-8 字节偏移、UTF-16 偏移和用户感知字符位置。
4. `EngineData` 等文字引擎载荷不是普通 JSON，也不应通过简单正则替换进行重写。
5. 字号、文档分辨率与几何变换需要分别保留；不要重复应用缩放。一般点值换算像素为 `px = pt × ppi / 72`，实际文字外观还受变换和字体度量影响。
6. 字体缺失、可变字体参数、复杂文字整形和路径文字会影响外观。未实现时保留文字源信息，并提供经过确认的外观版本。
7. “能够提取字符串”“能够编辑文字”“能够与 Photoshop 一致排版”是三项不同能力。

### 3.6 形状层、路径与填充层

形状层通常由填充、路径、可选描边以及形状参数组成。普通像素层或智能对象也能附加矢量蒙版，不能仅以 `vmsk` 判断内容类型。

#### 矢量蒙版

`vmsk` / `vsms` 常见载荷为版本号、flags 和路径记录。公开实现通常使用掩码 `0x01` 表示反相、`0x02` 表示未链接、`0x04` 表示禁用；不要把旧文档中从 1 开始的位描述机械解释为从 0 开始的 bit 编号。参见 [矢量结构实现][psd-vector-source]。

路径记录常为 26 字节：2 字节 selector + 24 字节记录内容。关键 selector 包括：

| selector | 内容 |
| ---: | --- |
| 0 / 3 | 闭合 / 开放子路径长度 |
| 1 / 2 | 闭合路径上的链接 / 非链接控制点 |
| 4 / 5 | 开放路径上的链接 / 非链接控制点 |
| 6 | 路径填充规则记录 |
| 7 | 剪贴板相关记录 |
| 8 | 初始填充记录 |

贝塞尔节点保存进入控制点、锚点、离开控制点。坐标常为相对文档尺寸归一化的有符号定点数，缩放因子为 `2^24`，每个点的分量顺序为 **y 在前、x 在后**。

```text
documentX = fixedX / 2^24 × documentWidth
documentY = fixedY / 2^24 × documentHeight
```

不要先把归一化路径坐标当成图层局部像素，再额外加一次图层偏移。超出 `0..1` 的路径坐标并不必然非法。

#### 填充与描边

- 纯色：保存颜色模式、颜色值和 Alpha 相关信息。
- 渐变：保存颜色停靠点、透明度停靠点、位置、角度、缩放、类型、反向和对齐等参数。
- 图案：保存图案标识、缩放、偏移，并确保图案资源实际可用。
- 描边：区分形状描边与图层样式中的描边；分别保存宽度、位置、连接、端点、虚线和内容。
- 多子路径：保留闭合状态、路径运算和填充规则，避免孔洞被填满或相交区域改变。
- 参数形状：如需继续编辑圆角等参数，不能只保留最终贝塞尔路径；应同时保留来源描述数据。

填充层即使没有有意义的普通像素缓存，也可能通过参数填满画布或蒙版范围。

### 3.7 智能对象

智能对象同时涉及**实例**与**源内容**：同一个源内容可以被多个图层实例引用，各实例还可能有自己的位置和变换。

| 部分 | 应记录的信息 |
| --- | --- |
| 图层实例 | 图层 ID、可见性、混合、透明度、蒙版和样式 |
| 内容关联 | 内部唯一标识、链接或嵌入类型、原始文件名 |
| 源内容 | 嵌入字节，或可解析的外部链接信息 |
| 几何 | 放置四边形、仿射或透视变换、warp 等 |
| 智能滤镜 | 参数、顺序、启用状态及滤镜蒙版 |
| 缓存 | 当前实例的像素结果，用于有限兼容显示 |

`SoLd` 等图层块与 `lnk*` 资源需要按内部标识关联，不能按“同名文件”关联。源内容可能为 PSD/PSB、位图、矢量文件或其他支持内容；不能统一假设为 PNG。

**实现建议：**

1. 分别处理嵌入和外链对象；文件中存在路径字符串，不等于外部内容一定可用。
2. 多实例可共享源内容。保留共享关系，避免编辑一个实例时意外改变独立副本的语义。
3. 位图缓存只能保留某个分辨率和状态下的结果，不能替代源对象的可编辑性。
4. 透视、弯曲和智能滤镜无法表达时，使用经过验证的缓存或 Photoshop 预渲染，并标记降级。
5. 对嵌套源文档限制递归深度和总解码量；遇到循环或无效引用应输出诊断。
6. 自动化工具不要仅因 PSD 中记录了路径或地址，就无条件访问任意外部资源；交付时按明确的素材根目录解析依赖。

**交付方式：** 自包含项目可采用嵌入对象；需要多人维护共享源素材时可采用链接对象并打包依赖。Adobe 提供 [链接对象嵌入][adobe-embed] 和 [打包、重新链接][adobe-package] 工作流。

### 3.8 调整层

调整层一般对下方合成结果执行颜色或色调运算，本身不一定包含可当作普通图片显示的内容。

| key | 常见调整 |
| --- | --- |
| `brit` | 亮度 / 对比度 |
| `levl` | 色阶 |
| `curv` | 曲线 |
| `expA` | 曝光 |
| `vibA` | 自然饱和度 |
| `hue `、`hue2` | 旧 / 新色相饱和度 |
| `blnc` | 色彩平衡 |
| `blwh` | 黑白 |
| `phfl` | 照片滤镜 |
| `mixr` | 通道混合器 |
| `clrL` | 颜色查找 |
| `nvrt` | 反相 |
| `post` | 色调分离 |

判断调整影响范围时，至少同时考虑位置、组边界、组混合模式、剪贴关系、蒙版与不透明度。只栅格化“调整层自己”通常无法得到有意义的独立图片；降级时可能需要预渲染其作用的整个合成子树。

未知调整算法应保留参数并报告不支持。不能把未实现的调整当作恒等变换后仍声称外观一致。

### 3.9 图层样式和智能滤镜

常见图层样式包括：投影、内阴影、外发光、内发光、斜面与浮雕、光泽、颜色叠加、渐变叠加、图案叠加、描边。

样式需要保存启用状态、参数、颜色、透明度、混合模式、缩放、全局光照依赖，以及同类效果的多个实例。不能假设每个图层最多只有一个投影或一个描边。

样式会扩大视觉范围，并受到 Fill、蒙版和高级混合选项影响。把所有样式统一放在蒙版之后绘制，可能得到错误结果。

`lrFX` 与 `lfx2` 等新旧表示可能同时存在，应按已验证的版本优先级读取，避免重复应用同一效果。未知或损坏的新版块也不意味着旧版一定能完整还原。

智能滤镜属于智能对象上的滤镜处理链，和图层样式是不同机制。参数可以包含插件相关信息；没有对应算法或插件时，应保留原数据并使用可验证的预渲染方案。

### 3.10 新功能、旧功能与私有字段

对生成式内容、某些特殊图层、插件数据、历史视频或 3D 内容等，不应根据名称推断二进制布局。

本机脚本字典仍包含一些历史类型枚举，这只能说明接口中存在该名字，不能证明当前版本仍完整支持创建和编辑该功能。

建议采用以下处理原则：

- 已识别结构且算法已实现：按原生语义导入。
- 结构已识别，但渲染或编辑不支持：保留原结构，使用经过验证的外观降级。
- 未识别结构且有可靠合成结果：明确标记为预览或扁平化内容。
- 没有可用数据或无法可靠解析：给出明确诊断，不静默输出空白或删层。

### 4.2 Opacity、Fill 与 Alpha

三者应分开处理：

1. 像素 Alpha 描述该像素的覆盖或透明程度。
2. Opacity 调节整个图层及其效果的最终贡献。
3. Fill 主要调节内容，还可能与特定混合和高级样式语义发生交互。

例如：文字设置 `Fill=0%`，仍可能显示描边或投影；若把整个结果的 Alpha 直接置零，这些效果也会消失。

仅在没有额外蒙版、效果和特殊混合的简化 Normal 模型中，可用以下公式说明 source-over：

```text
As：上层有效 Alpha；Ab：下层 Alpha
Cs、Cb：相同计算空间中的非预乘颜色

Aout        = As + Ab × (1 - As)
CoutPremul  = Cs × As + Cb × Ab × (1 - As)
Cout        = CoutPremul / Aout，Aout > 0 时
```

该公式不是完整 Photoshop 合成算法。组、Fill、Blend If、挖空、剪贴、样式、颜色配置和高位深处理均可能改变实际步骤。

### 4.3 剪贴关系与组隔离

剪贴链应按相邻层和层级识别，并确定具体基底。在面板从上到下的表达中，上方被剪贴层依赖下方对应的基底层。重新排序、拆组或单独导出可能破坏这个关系。

Pass Through 允许组内图层与组外下方内容发生相应混合；隔离组通常先合成子内容，再将整个组参与外部混合。组蒙版、组不透明度、调整层和高级混合还会影响结果。

因此，下列操作都不能默认是无损的：

- 把 Pass Through 改为 Normal。
- 把所有子层的不透明度分别乘以组不透明度。
- 拆出剪贴层但不带其基底。
- 把组内调整层移到组外。
- 删除看似没有像素的蒙版基底、调整层或组。

组和高级混合的应用语义参见 [Adobe 混合模式][adobe-opacity] 与 [高级混合选项][adobe-advanced]。

### 4.4 色彩与坐标

**色彩处理：**

- RGB 数值必须结合 ICC 配置解释。将 Display P3 或 Adobe RGB 数值直接当作 sRGB，可能出现明显色差。
- “指定配置文件”和“转换到配置文件”是不同操作；前者改变数值解释，后者以保持颜色外观为目的转换数值。
- CMYK、Lab、灰度、专色、多通道不能直接拼成 RGBA。
- 对 16/32 位文档应明确保留精度或转换策略。HDR 到 SDR 还可能需要色调映射。
- 比较两个渲染结果前，应统一颜色空间、Alpha 表示、尺寸和背景条件。

**坐标处理：**

- 文档、画板、图层像素、蒙版、文字局部、路径归一化和智能对象源坐标分别保存。
- 文档坐标允许负值，先保留，再在输出阶段裁剪。
- 阴影或外描边的视觉范围可能超出内容矩形，裁图时需要留出实际扩展范围。
- 不要因为数值最初是整数矩形，就把文字、路径和变换中的小数坐标全部取整。

### 4.5 推荐解析流程

1. 校验签名、版本、尺寸、位深和模式，建立文件范围。
2. 读取颜色数据和资源，保存 ICC、分辨率、全局效果状态等依赖。
3. 读取图层与蒙版区，建立有边界的子读取器。
4. 扫描主 Layer Info 和文档级附加块，按位深和版本选择适用的图层集合。
5. 读取全部 Layer Record、通道表及 Extra Data，保留原始索引和未知块。
6. 按通道表定位数据，选择图层或蒙版尺寸，逐通道解码并核对长度。
7. 解析已识别的内容、Descriptor、路径、样式和外部内容引用。
8. 由 section divider 恢复层级，归一化数组方向和剪贴关系。
9. 计算有效可见性，建立画板、组和依赖资源之间的关系。
10. 按工具能力执行原生渲染、预渲染降级、仅预览或明确拒绝。
11. 输出结构、资源和诊断信息；回写时重算长度、引用与缓存状态。

建议每个解析函数只在父区边界内操作，并返回实际消费字节数。日志应能定位到图层 ID、记录序号、key 和文件偏移。

### 4.6 未知字段与回写

读取器、渲染器和写入器应分别声明能力。能读出图层树，不代表能正确合成；能正确合成，不代表修改后能够无损保存。

**实现建议：**

- 保留未知资源和未知附加块的原始字节、顺序、作用域以及长度信息。
- 不随意把重复 key 压成单个字典项；在确实有覆盖规则前先保留有序列表。
- 未知 Descriptor 值无法确定边界时，退回保留整个外层块。
- 修改已知字段后，未知块可能仍包含旧引用、旧坐标或缓存。单纯复制未知字节不能保证修改后的文件语义一致。
- 复制、删除、重命名或重新编号图层时，更新已理解的相关引用；无法验证一致性的修改应报告限制。
- 不把旧合成缓存继续标记为更新后的真实合成结果。
- 保存前确认长度宽度、对齐和所有父区长度都已重算，必要时切换为 PSB。

### 4.7 建议的兼容性声明

建议用下表分别描述某项功能，而不是只写“支持 PSD”。

| 维度 | 示例状态 |
| --- | --- |
| 结构读取 | 已完整解析 / 仅识别 / 原样保留 / 不支持 |
| 外观 | 与基准验证一致 / 有近似 / 使用缓存 / 不可显示 |
| 编辑 | 可编辑 / 部分可编辑 / 仅查看 |
| 回写 | 已验证 / 未验证 / 不支持 |
| 资源依赖 | 自包含 / 需要字体 / 需要链接文件 / 需要插件 |

若用于 PAG、PAGX 或其他引擎，应按目标版本逐项建立映射和验收样本。本文没有宣称当前仓库已经实现某种 PSD 导入能力。

下列是面向后续实现的**测试建议**；仅第七部分列出的检查是本次已完成的核验。

| 样本组 | 需要覆盖的问题 |

## 五、设计制作与图层交付规范

本部分为**交付约定**。其中“必须”表示采用本规范的项目应满足的验收条件，不表示 PSD 格式本身有此限制。“建议”允许项目说明中记录例外。

### 5.1 交付前必须明确的项目参数

| 参数 | 必须说明的内容 |
| --- | --- |
| 使用场景 | 屏幕界面、平面设计、照片处理、印刷、动效或程序导入 |
| 目标环境 | Photoshop 版本、目标应用/引擎及版本、接收方平台 |
| 文件规模 | 画布尺寸、画板数量、PSD 或 PSB |
| 色彩 | 颜色模式、位深、ICC 配置、是否需要色彩转换 |
| 输出尺寸 | 基准像素尺寸、倍率、输出格式和透明背景要求 |
| 可编辑要求 | 哪些文字、形状、智能对象或效果必须保留可编辑性 |
| 兼容范围 | 支持的混合、蒙版、样式、字体和外部素材形式 |
| 对照基准 | 哪张预览图、哪个图层复合或哪个可见状态是最终效果 |

以上参数应写在交付说明中，不能只存在于聊天记录或设计者记忆里。

### 5.2 文档设置

| 场景 | 建议设置 | 验收重点 |
| --- | --- | --- |
| Web / App / 常规屏幕素材 | 按目标像素尺寸制作；常规兼容交付优先 RGB、8 位、明确的 sRGB 输出 | 像素尺寸、透明背景、目标应用颜色一致 |
| 广色域屏幕设计 | 明确源配置与目标配置；必要时另交 sRGB 版本 | 不把广色域数值直接按 sRGB 使用 |
| 照片精修 | 保留所需精度及源色彩配置，另出交付图 | 不因交付方便过早降到 8 位或丢失色彩资料 |
| 印刷 | 采用项目与印厂确认的尺寸、分辨率及配置 | 出血、有效分辨率、色彩转换和输出要求 |
| HDR / 高位深 | 明确 16/32 位、目标查看环境及 SDR 预览方式 | 亮度范围、精度、色调映射 |
| 动效 / 程序导入 | 以目标引擎实际支持的子集为准 | 独立元素、坐标、遮罩、混合和替换素材 |

屏幕素材的像素尺寸由宽高决定；仅把分辨率从 72 PPI 改为 300 PPI，并不自动提高相同像素尺寸图像的清晰度。涉及印刷、点字号或重采样时，分辨率参数才有相应作用，操作时应注明是否进行了重采样。

必须保留或明确说明 ICC 状态。不能把未嵌入配置的文件作为跨软件颜色一致的唯一依据。

### 5.3 PSD/PSB 文件命名

建议统一采用：

```text
{project}_{page_or_asset}_{width}x{height}_{status}_v{NNN}.psd
```

示例：

```text
atlas_home_1440x1024_review_v003.psd
atlas_home_1440x1024_approved_v004.psd
atlas_poster_8000x12000_approved_v012.psb
```

约定：

- `project` 和业务名称使用团队共享词汇，自动化链路优先小写英文、数字和下划线。
- `status` 使用固定集合，例如 `draft`、`review`、`approved`。
- 版本号递增，不使用“最终版、最终版2、最终不改版”等无法排序的名称。
- 多画板文档若尺寸不同，使用 `multi` 代替单一尺寸，并在说明中列出每块画板尺寸。
- 文件名与实际尺寸、格式保持一致，不能改扩展名冒充格式转换。
- 项目需要日期时，统一采用 `YYYYMMDD`，不要混用多种日期格式。
- 不以覆盖旧版本的方式删除必要的审阅依据；发布版本在变更记录中说明对应改动。

中文文件名和图层名本身是允许的。英文命名是自动化交付的可选团队约定，不是 PSD 的字符限制。

### 5.4 图层命名

建议使用“类型 + 业务语义 + 可选状态/序号”：

```text
{type}_{meaning}[_{state}][_{index}]
```

| 前缀 | 用途 | 示例 |
| --- | --- | --- |
| `grp_` | 普通图层组 | `grp_header` |
| `art_` | 画板 | `art_home_desktop` |
| `txt_` | 可编辑文字 | `txt_hero_title` |
| `img_` | 像素图像 | `img_product_photo` |
| `shp_` | 矢量形状 | `shp_button_background` |
| `ico_` | 图标业务元素 | `ico_search`；实际可为形状或智能对象 |
| `so_` | 智能对象 | `so_brand_logo` |
| `adj_` | 调整层 | `adj_photo_curves` |
| `fill_` | 填充层 | `fill_page_gradient` |
| `bg_` | 背景业务元素 | `bg_page`；不强制是特殊 Background 层 |
| `ref_` | 参考内容 | `ref_layout_example` |
| `guide_` | 说明或辅助内容 | `guide_safe_area` |

命名要求：

1. 正式输出元素必须能从名称识别用途，不保留大量 `Layer 1`、`图层 23 拷贝 7`。
2. 同一父组内的正式输出项应避免同名；不同组件内可以使用同样的局部名称，通过完整层级路径区分。
3. 类型前缀与实际内容应尽量一致。`ico_`、`bg_` 是业务语义，不能被解析器强制当作技术类型。
4. 状态统一采用 `default`、`hover`、`pressed`、`disabled`、`selected` 等团队约定值。
5. 稳定的业务标识与显示名称分开维护，不能用图层显示名取代所有程序引用。
6. 颜色标签可用于工作状态或模块分类，但验收信息必须同时可由名称或说明读出。
7. 自动导出链路应限制路径分隔符和可能被命名解析器解释的特殊符号。
8. 如果项目使用 Generator 等基于名称的导出规则，名称中的扩展名、倍率或分隔符属于功能配置，应在交付说明中明确，不能按普通命名规范随意清理。

### 5.5 分组层级

建议按“页面/画板 → 业务模块 → 组件 → 元素”组织。建议大部分内容在 2～4 层内完成，但这只是可维护性建议，不是最大允许深度。

以下示例按 Photoshop 面板从上到下排列：

```text
art_home_desktop
├── grp_overlay
│   └── grp_modal
│       ├── txt_modal_title
│       ├── ico_close
│       └── shp_modal_panel
├── grp_header
│   ├── so_brand_logo
│   └── grp_navigation
│       ├── txt_nav_products
│       └── txt_nav_about
├── grp_hero
│   ├── txt_hero_title
│   ├── txt_hero_description
│   ├── grp_primary_button
│   │   ├── txt_button_label
│   │   └── shp_button_background
│   └── grp_hero_image
│       ├── adj_photo_tone       [剪贴到下方图像]
│       └── img_photo_base       [带像素蒙版]
├── grp_footer
│   └── txt_copyright
└── bg_page
```

组织要求：

- 一个业务模块使用一个明确的顶级组，避免同一组件的文字、图片和阴影散落在无关位置。
- 组件内按实际遮挡关系排列，不能只为字母排序而改变叠放顺序。
- 独立运动或独立替换的元素保留独立图层或组。
- 剪贴链与其基底放在同一个明确作用范围中，并在必要时加以说明。
- 调整层放在它应影响的内容范围内；不能默认一个组一定会隔离调整。
- 普通模块是否使用 Normal 隔离、还是 Pass Through，应由实际视觉目的决定并检查结果。
- 参考图、说明和历史版本放在独立参考区域、参考文档或明确不参与输出的组中。禁止仅靠“当前没看见”判断不会被导出。

### 5.6 文字图层制作

**必须：**

- 仍需修改的标题、按钮文案、正文保留文字层。
- 说明字体的准确名称、样式/字重、来源，以及可变字体使用的轴值。
- 在最终环境检查中文、英文、数字、标点、特殊符号和换行。
- 检查是否发生字体替代、缺字、溢出、行高变化或文本框裁切。
- 标识需要逐字替换、多语言替换或程序动态填充的文字区域。

**建议：**

- 按语义拆分文字层，不把整页不相关文字塞在同一个层里。
- 同一段落使用文字样式和段落样式管理，不依赖大量手动空格对齐。
- 需要保留混合样式时，在说明中标识一个层内存在多种字体或字号。
- 对接动画或程序时，提供允许的最大行数、替换后的边界和溢出策略。

如接收工具不支持该文字外观，应同时交付可编辑源稿与确认过的外观版本，并写明哪个版本用于修改、哪个用于显示。不能以栅格化文字替代唯一可编辑源稿。

### 5.7 图片、透明边缘与智能对象

| 对象 | 必须检查 | 建议做法 |
| --- | --- | --- |
| 普通图片 | 实际像素是否足够、是否存在非预期拉伸 | 保留原始素材和来源关系 |
| 透明素材 | 边缘白边/黑边、半透明过渡、裁切是否正确 | 在深色和浅色背景各检查一次 |
| 可替换图片 | 放置范围、裁切逻辑、保持比例方式 | 明确哪些区域允许替换 |
| 品牌标志 | 可编辑源或高质量来源、是否被低分辨率栅格化 | 适用时保留矢量源或智能对象 |
| 嵌入智能对象 | 源内容可打开、变换和滤镜结果正确 | 适合需要自包含的交付 |
| 链接智能对象 | 链接完整、移动交付目录后仍可解析 | 使用打包工作流并保留依赖目录结构 |
| 共享智能对象 | 哪些实例共享内容 | 在说明中提示“一处编辑、多处更新”关系 |

不得把局部机器上的绝对路径当作接收方一定可用的素材地址。打包后应从交付目录重新打开检查，必要时使用 [Adobe 的 Package 和 Relink 流程][adobe-package]。

透明留白是否裁除由用途决定：静态图片可按约定裁紧；动效、换肤、序列帧和需要稳定对齐的素材可能必须保留统一画布。禁止为了减小尺寸而擅自改变定位基准。

### 5.8 形状、蒙版与剪贴

**形状：** 仍需缩放或改颜色的简单界面元素优先保留矢量形状。圆角、描边、渐变和路径孔洞应在目标环境确认，避免转换后轮廓改变。

**蒙版：**

- 非破坏性裁剪优先保留蒙版，不直接删除唯一源图像的边缘内容。
- 蒙版必须附着于实际要限制的层或组。
- 检查蒙版是否禁用、是否反相、是否有羽化或降低浓度。
- 需要移动对象时，明确蒙版是否随对象移动。
- 像素与矢量蒙版共存时，检查最终交集和边缘是否符合预期。

**剪贴：** 被剪贴层与基底一起交付。导出单个组件前确认输出工具是否会携带或计算剪贴关系，避免输出整张未裁剪图片。

不应把所有蒙版“应用”或把所有剪贴关系“释放”作为通用清理步骤。这些操作会改变可编辑性或外观。

### 5.9 样式、混合与调整层

正式源稿允许保留所需的复杂效果；兼容输出稿必须遵守目标工具已经验证的能力范围。

| 特性 | 交付要求 |
| --- | --- |
| 图层样式 | 确认效果启用、多个实例、全局光照与视觉边界 |
| Opacity / Fill | 分别检查，不能把 Fill=0 的层直接当作空层删除 |
| 混合模式 | 非 Normal 的层和组需在目标环境验证 |
| 调整层 | 明确影响范围，尤其注意 Pass Through 和剪贴 |
| Blend If / 挖空 | 若目标不支持，提供明确的预渲染方案 |
| 智能滤镜 | 保留源对象；说明需要的 Photoshop 或插件条件 |
| 未支持效果 | 标明降级范围，不静默去掉效果 |

**预渲染范围应按依赖确定。** 某个效果依赖下方背景时，只导出当前图层的透明 PNG 不一定能还原原效果；可能需要把整个组件、组或画面合成后输出。

兼容处理后，应使用同尺寸基准图比较。不得批量更改混合模式、羽化、组状态或颜色配置后直接作为已验收结果。

### 5.10 隐藏图层、空图层与辅助内容

允许保留有明确用途的隐藏层，例如备选状态、替换素材、动画预备元素或模板占位符。交付时应标明用途。

清理要求：

- 删除确认无用途的临时重复项，但保留必要的可编辑来源和版本记录。
- 空像素层、空组可以清理；有业务占位意义的内容需命名并说明。
- 不以“图层矩形为空”判定调整层、填充层或组没有作用。
- 不以“肉眼看不见”判定图层可以删除；它可能是剪贴基底、挖空、引用或其他状态所需内容。
- 参考、备注、辅助标记必须有明确的不输出策略，并在实际导出结果中核验。
- 最终保存时的默认可见状态应对应交付说明中的主效果。

### 5.11 动效和程序导入的附加要求

本节只在项目需要动画、PAG/PAGX 或其他程序化导入时采用；实际支持项以具体工具版本为准。

1. 一个独立动画对象保留为一个可识别的层或组，不提前与背景合并。
2. 明确坐标原点、锚点/旋转中心、设计分辨率和目标输出分辨率。
3. 分别说明图层内容边界和用于对齐的固定边界。
4. 需要动态替换的图片、头像、文字、颜色使用稳定的业务标识。
5. 检查空白边距、阴影扩展和蒙版范围，避免运动过程中被裁切。
6. 复杂混合、调整层、透视、warp 和智能滤镜采用目标工具验证过的表达；必要时预渲染相关组件。
7. 有多个 UI 状态或图层复合时，提供状态清单和默认状态，不能指望导入器自动推断。
8. 不把 Photoshop UI 的折叠状态、选中状态或图层颜色标签当作动画逻辑。

### 5.12 源稿与兼容输出稿

建议在存在兼容转换时交付两种明确角色的文件：

| 文件角色 | 内容 | 使用目的 |
| --- | --- | --- |
| 设计源稿 | 保留文字、形状、智能对象、蒙版、调整和必要效果 | 后续修改与设计维护 |
| 兼容输出稿 | 按目标工具约束转换；必要元素已预渲染 | 程序导入、动效制作或指定下游处理 |

两者应有对应版本，并在交付说明中列出差异。例如“组件 A 的内发光已合成到图片”“文字 B 在输出稿中栅格化，源稿仍可编辑”。没有发生兼容转换时，无需为了形式重复制作两个相同文件。

### 6.3 交付操作顺序

1. 确认源稿版本、默认可见状态与效果预览一致。
2. 按模块检查图层命名、层级、剪贴关系和必要的可编辑内容。
3. 检查字体、链接智能对象、图案和插件依赖。
4. 按目标能力制作必要的兼容输出稿，并记录转换范围。
5. 使用 PSD/PSB 保存源稿，保留项目需要的图层与颜色配置；跨软件预览有需求时启用适当的最大兼容性设置。
6. 在固定尺寸、固定颜色条件下导出预览和实际资产。
7. 打包文档与依赖，完成交付说明。
8. 从交付目录重新打开文件，检查链接和字体；在目标工具中验证实际输出。
9. 对照基准完成视觉验收，记录已知差异与接受范围。
10. 确认最终文件版本、预览、兼容稿和说明相互对应。

“Export As”“快速导出”等图片输出不能替代保存可编辑 PSD 源稿。保存方式应以最终是否保留所需图层数据为验收依据，参见 [Adobe 保存文档说明][adobe-save]。

### 6.4 设计交付验收清单

以下复选框供交付人员实际检查，并非本次已经对某个设计项目执行的验收记录。

**文件与文档**

- [ ] 文件能够完整打开，无损坏或格式不匹配提示。
- [ ] 文件名、版本号、状态与说明一致。
- [ ] 画布、画板、输出倍率和实际像素尺寸正确。
- [ ] 颜色模式、位深、ICC 和分辨率符合项目约定。
- [ ] 默认可见状态与主预览一致。
- [ ] 超出 PSD 限制时采用合适的 PSB，并确认接收工具支持。

**层级与命名**

- [ ] 顶级模块、组件和独立元素有可理解的名称。
- [ ] 正式输出项无误导性同名和大量无意义默认名。
- [ ] 图层顺序、组结构和画板归属正确。
- [ ] 剪贴链、蒙版和调整层的作用范围正确。
- [ ] 隐藏层、空层和参考内容均有用途或已清理。
- [ ] 参考、说明、辅助内容没有混入实际输出。

**内容与依赖**

- [ ] 无非预期的缺字、字体替换、断行或溢出。
- [ ] 字体清单和必要的素材来源信息齐全。
- [ ] 链接素材已打包，移动交付目录后能正确解析。
- [ ] 图片分辨率、比例和透明边缘符合用途。
- [ ] 共享智能对象与独立副本关系已确认。

**外观与兼容**

- [ ] Opacity、Fill、混合模式和组模式经过检查。
- [ ] 样式、阴影、描边、羽化和高级混合没有丢失。
- [ ] 裁图没有切掉必要的效果边缘或稳定对齐留白。
- [ ] 每种状态都有对应预览或明确说明。
- [ ] 兼容稿的栅格化、预渲染和已知差异已经记录。
- [ ] 已在目标工具实际导入或打开，并与基准比较。

### 6.5 解析器与导入器验收清单

- [ ] 正确区分 PSD 与 PSB 的长度字段。
